# Rigid actor GPU skinning: Linux host verification

The opt-in `gpu_skinning` switch defaults off. The implementation accepts only whole surfaces with one unit weight on one common bone; it implements no general multi-bone GPU skinning. Cofactors of the actual affine map preserve area-normal semantics for mirrors and packed non-unit rotations. Numerical conditioning, edited UV/topology, normal-driven layers, shells, late overlays, resource limits or rejected shaders retain the exact CPU kernel and persistent workers.

`src/render_fx/gpu_skinning.rs` owns bounded immutable buffers and reusable descriptors on the game thread. Weak immutable identities and owning frame handles prevent stale address reuse. Static payloads are limited to 128 surfaces/2 MiB, descriptors to 1,024. GPU packets are merge barriers; program transitions invalidate the original submission/uniform caches. Transparent centres use original CPU position arithmetic over immutable offsets. The shader uses four attributes, 12 varying floats and 15 vertex uniform vectors; per-draw deformation is 112 bytes plus the retained fragment uniforms. Vita-only pair compilation checks binaries before linking and restores the previous compiler semantics.

Linux evidence: 840 renderer-feature tests, four final GPU tests and the default-feature check pass. Against the existing CPU kernel, 12,582 accepted real surface/pose cases have maximum position error 0.00048828125 world units, normal error 0.007136 degrees, RGB error one byte and exact alpha. Singular/degenerate, influence-limit and ownership/allocation cases are covered.

Same-machine 1200×680 captures: CPU-off equals the exact J19 baseline in all 109 inherited reference/alpha/six-map captures. GPU-on actor interiors differ by at most two channel bytes; raster edges stay within one pixel, with maximum edge channel error 14 reported separately. Sixty additional on/off near/far actor witnesses cover authored alpha, Alice ghost and NPC dissolve. The warmed descriptor/static-cache path records zero allocation calls and zero static upload bytes; this does not claim allocation-free full-frame presentation.

Actual village reference GPU coverage is Alice material4/material5, two surfaces/30 vertices; 47 surfaces/4,622 vertices retain CPU skinning. Local actor witnesses admit Alice material4/material5/material7/material9 (64 vertices). Cheshire, club, rabbit, gnome and child witnesses retain CPU output because of rigid eligibility or material/consumer preservation. Candidate load-time rigid counts alone do not establish visible GPU coverage.

Frozen host medians: skin gather 132→148 µs, worker service 505→508.5 µs, collect wait 1→1 µs (off→on). Geometry upload bytes are zero in both frozen arms; GPU deformation adds 224 bytes/frame. Shared-machine total timing is confounded, and Linux deferred counters are incomplete. No host performance gain is established. The initial 0–0.4 ms console gain remains an assumption; regression is possible. Vita shader acceptance, performance and memory remain untested. General GPU skinning's proposed 3–5 ms gain is unsupported by this subset. No device access occurred; dependencies and SDK inputs remain pinned.
