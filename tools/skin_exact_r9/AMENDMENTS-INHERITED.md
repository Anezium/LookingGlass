# Orchestrator amendments to CONSOLE-BRIEF.md (r7-skin)

These amendments come verbatim from REVIEW.md. They are binding and take precedence over CONSOLE-BRIEF.md
wherever the two conflict. CONSOLE-BRIEF.md itself is unchanged, so its sealed hash
(7ccda752…) stays valid. The pilot reads both files and verifies both hashes.


1. Promotion block. `skin_actual_consumers` stays default false and must not be enabled in any shipped or merged configuration, whatever these console results show. Three exactness defects must be fixed first. (a) `Model::draw_card` (src/npc/card_art.rs:183) calls `draw_frozen` with no FROZEN consumer, so frozen Puppet card guards in Keep and Grounds2 read a stale shared mesh. (b) `Puppet::draw_afterimage` (src/npc.rs:871) renders mesh normals through the light-atlas branch (src/render.rs:65), and in the ON arm those normals are stale for Puppets drawn both normally and as afterimages (the Cheshire cat, funhouse and jabberwock performers). (c) All instances of one Puppet share one ActorId and one two-slot bank, and the `unchanged` version skip (src/render_fx/actor_publication.rs:94) does not check that the slot's previous contents came from the same instance. A fix must leave default-off pixels unchanged. The rebuilt SELF must then pass new host fixtures: a frozen card guard Puppet with at least two instances; a cat normal draw followed by an afterimage fade-out; and one Puppet drawn as two or three instances where the instance set changes while one instance is bit-static. Each fixture compares a PNG on every frame, not only the final one. The rebuilt SELF must also reproduce, exactly, the r7 host serial/worker vertices per frame on Pandemonium (903.425/4014.575 ON) and Hedge3 (4.042/1746.958), so this console measurement stays attributable to the fixed code.

2. Scope of a result. A Pandemonium BENEFIT qualifies only the cost of moving Puppet skinning to the workers on that idle scene. It is not exactness evidence. Hedge3 has an identical host workload in both arms and serves only as a noise and SELF control. Report this explicitly in RESULTS.json and DECISIONS.md.

3. Worker critical path. From census A5 and B6 on each map, report actor_collect (median, p95, max over the 120 measured rows) and worker_skin_ns for each worker (median, p95, max), plus their B6 minus A5 differences. Label the map WORKER_ON_CRITICAL_PATH if the B6 actor_collect median exceeds A5 by more than 0.5 ms or B6 actor_collect p95 exceeds 1.0 ms. Worker 1 shares CPU2 with the PCM producer and the music decoder at lower priority. In every wall arm, report the producer p95 range per arm and the B minus A difference, even when every value is below 8 ms.

4. Census reading. Census A5 and B6 open different numbers of actor sub-brackets (actor_serial_skin exists only for serial surfaces). Their actor_gather and sub-bracket differences therefore include unequal observer cost. Never present a census B6 minus A5 difference as a performance gain. The wall ABBA is the only performance evidence.

6. Comparator text. The docstring of console/compare-abba.py states the rules inverted. The `classify` function is authoritative: Pandemonium BENEFIT requires both oriented median deltas strictly below -1000 µs, and Hedge3 NONREGRESSION requires both at or below +1000 µs, after rounding arm medians to integer µs. Quote the rule from the brief, not from the docstring, in any report.

7. Allocation claim. "No added allocation" is established only for the measured steady-state host frames inside capture_single. Bank creation, the 120-frame unused eviction and later re-creation, and lookup growth can allocate in B at transitions, and none of these were measured. Report the B2-A1 and B3-A4 benchmark heap differences under the existing +1 MiB rule and make no zero-allocation or no-transition-allocation claim.
