# Exact skin consumers r9

The optimization writes eligible body surfaces into owned worker publication banks. Live mesh consumers must declare serial preparation before the body is drawn. A per-model freshness assertion protects frozen/electric readers and ambient LOD snapshots. An afterimage capability must be declared at model construction; normal body draws then preserve the serial normals across later fade frames. Afterimages continue to inherit those normals and UVs exactly, including their light-atlas shader behavior.

Card guards and every resident frozen body declare the frozen consumer. Existing guard/imp/clock/chess/ant/magma, electric, Alice ice/rage and material-recipe fallbacks stay protected. Attachments use their own TAN preparation and skeletal tags, not the body's skinned vertex positions. Contact shadows use collision/feet; reflections prepare independent models. First-person weapon meshes do not consume third-person skin output.

Each numeric draw has a persistent instance token matched to at most one prior draw with the same exact transform and render parameters. Duplicate transforms claim distinct prior draws. Each publication slot stores its last instance token; unchanged inputs can retain a version only when the destination's instance, CPU topology, live UV, alpha variant and immediately preceding epoch all match. Changing order or removing an earlier shared instance therefore invalidates stale GPU uploads and merged geometry.

The host-only oracle reads actual bound OpenGL buffers at each draw, including upload-cache hits. It compares all position/normal/UV/color/index bits to intended packets and compares every frame across off/on. Dedicated real-asset fixtures hash the framebuffer on each of 180 frames per case. Production builds exclude all readback/fixture code. Numeric bounds, kernel arithmetic, two workers, dispatch/collect order and fallback behavior are retained.

Transition allocation remains bounded; see the explicit amendment and report. New provenance/capability fields and guards allocate nothing. The lever stays default false until review and new console qualification.
