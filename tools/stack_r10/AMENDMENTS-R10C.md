# r10c amendments, what changed in code

`REVIEW-AMENDMENTS.md` keeps the review text verbatim. This file says which of those findings this seal changed. `CONSOLE-BRIEF.md`, `AMENDMENTS.md`, `AMENDMENTS-R10.md` and `AMENDMENTS-3.md` were not edited. `collision_sah` and `skin_actual_consumers` stay default-off.

## Blockers

- **B1, fixed.** `smoke_admission.inspect` refuses `SYNTHETIC-OFFLINE-ONLY` and `synthetic_offline_only: true` on `SESSION.json`, `RESTORE-FINAL.json` and each run `AUDIT.json`. A real smoke needs driver request and response ids, `DRIVER-READY` pid/start/expiry recorded beside `DRIVER-ADMISSION`, an FTP ledger with a port-1337 connected receipt and a sha256, and a device inventory hash that matches file bytes. `--retain-smoke` is gone. The synthetic e2e stamps every session it creates. Main admission takes `--smoke-fixture` outside the package and does not write a session directory into OUT. The receipt key is `smoke_fixture_admission`, with `hardware_smoke: false`. The r10 key `real_smoke_admission` is not written. Negative fixtures cover a synthetic smoke at the smoke path, the same tree copied onto the package OUT path, and a real-looking smoke with the driver provenance removed.
- **B2, fixed.** A missing benchmark sample does not raise. Hedge3 must have a non-None benchmark sample under 165 MiB, and the refusal says so. Pandemonium's benchmark plateau is `unavailable` when the sample is missing, and 165 MiB is not applied to it. Pandemonium heap is not a smoke gate. `make-report.heap_status` returns `HEAP_NOT_CONFIRMED` when any of the four wall samples is missing. Fixtures cover the Pandemonium gap, the Hedge3 refusal, and the report helper.

## Numbered amendments

1. **Fixed in code.** `run_health.health_text` stops on `[lg/skin] serial fallback` and `afterimage consumer must be declared` across the whole log. `audit-run.py` asserts the same lines are absent, records `serial_fallbacks=0`, and rejects a frame-total line whose count is not 0. The same log assert is in `host_exact.py` and `host_stack_oracle.py`.
2. **Fixed in code.** The `&Model` to `&mut Model` cast and `invalid_reference_casting` are gone. `require_live_skin`, `draw_electric`, `draw_frozen` and `Cache::capture` take `&mut self`. The release body is `release_live_fallback` / `release_serial_fallback`, compiled in every build. `serial_fallbacks()` is exported outside `cfg(test)`, in the census JSON and on the frame-total log line. The new fallback tests call that body. `cargo test --release` executes it. `skin_actual_consumers` is still not the default.
3. **Wording kept verbatim in `REVIEW-AMENDMENTS.md`.** The code no longer leaves a stale mesh when this frame gathered no draw: `release_serial_fallback` replays the gathered draw when one exists, and otherwise runs the serial kernel on the current pose (or a rest pose if none was stored). The review's sentence that the old fallback was not exact in the no-draw case remains in the verbatim file. It describes the r10 behavior, not this seal.
4. **Fixed by the retained host logs** in `proof/HOST-TESTS.json` and the equality/oracle receipts. The all-on versus all-off run uses `LOOKING_GLASS_SAH_SILENT_AUDIO=1` and requires a nonzero acoustic-cache counter on the all-on census arm.
5. **Recorded, not rewritten.** The r10 `STACK-ORACLE.json` and `STACK-SIMULATION-EQUALITY.json` used `--no-audio` and prove SAH plus skin only. The map oracle compared per-frame packets and the final PNG. No intermediate images were compared on maps. The r10c rerun of those two proofs uses the silent mixer so the acoustic cache runs. That rerun does not change the verbatim amendment.
6. **Wording fixed in `READING-RULES.md`, which `prepare.py` copies into `CONSOLE-PROTOCOL.json` `pass_rule`.** `MEASUREMENT-LIMITS.md` and `CONTRACT.md` carry a short header: where they disagree with `AMENDMENTS-R10.md` or `READING-RULES.md`, the later files win. `AMENDMENTS.md` was not edited. This file is the record that its r8 sentences are superseded where they disagree with `AMENDMENTS-R10.md`.
7. **Fixed before data.** Promotion stays at or under +1 ms. `compare-abba.py` adds `pandemonium_descriptive_below_minus_1ms` (`BOTH_BELOW_MINUS_1MS` or `NOT_BOTH_BELOW_MINUS_1MS`). `make-report.py` prints that label. The synthetic e2e still expects `REGRESSION` then `NO_CONFIRMED_BENEFIT` and overall `NO_PROMOTION`.
8. **Not changed in this seal.** `campaign::arrive` still builds a world of its own. No host check for a single SAH line on a normal Hedge3 exit was added. `collision_sah` stays default-off. This remains a before-default-on condition.
9. **Wording in `READING-RULES.md`.** A census validation failure on the census B launch is a diagnostic failure. It does not invalidate the wall. No collection stop was retargeted.
10. **Recorded in the package report.** The host binary's source revision is the branch head of the native build. Both native build receipts are kept, and the SELF bytes match. Parents `c046ba6` (r8 SAH, contains r6 audio) and `c853af5` (r9 exact skin). `DECISIONS.md` in the port repository was not rewritten by this seal.
