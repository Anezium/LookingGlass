# r11 transition memory amendment

The r8 memory failure is an engine defect. Reordering the pilot's operations or removing a recorder is not the engine fix. This package retains Hedge3 → native Load of the human Pandemonium Auto → chapter back to Hedge3, first all three levers OFF, then all three ON, with one common SELF.

The required r10b integration candidate does not contain r8's `audio_cache_qualification` recorder or config key. Passing its old config would fail strict renderer configuration parsing. This package therefore uses the validated r10c configs, differing only in `collision_sah`, `skin_actual_consumers`, and `audio_static_cache`. The old 7.125 MiB recorder reservation is absent. The transition logger is always on and samples heap/arena during allocations and phase boundaries. This is a stated memory-workload difference from the crash recording; the operation sequence is unchanged. Do not claim the r8 recorder workload was qualified.

The fixed pass rule is no crash/OOM, three successful expected entries in order, before/after heap and arena for each, a release sample for both live-scene replacements, and every observed transition `peak_heap_used` strictly below 170 MiB. A missing sample is FAIL_OR_UNKNOWN. Peaks are sampled newlib values, not continuous process RAM. No cache, collision, or skin optimization is promoted by this protocol.

M3: resume with Circle only from an inspected modal Main Start menu whose legend offers Circle Back. The paused gameplay overlay is insufficient. M4B: process kill via `quit ALICELG01`, repeat and require the exact cannot-quit error, then inspect and acknowledge a HOME/LiveArea image before any restoration. No in-game Quit during restoration.

This amendment is a separate file. No historical brief or evidence was rewritten. The package was prepared and tested offline; console execution is not authorized here.
